01APEXA · beamline update · Aug 2026

A context-engineering fix
for our beamline AI

APEXA is a multi-agent LLM assistant that writes MIDAS parameter files and runs HEDM analysis from a plain-language request. It kept making a specific class of mistake — and the root cause was not the model, but what we put in front of it. This is a context-engineering story.

LLM agent
A model in a plan → act → observe loop with tools. APEXA routes a request to a specialist agent (calibration, analysis, …).
Context engineering
Deciding what information enters the model’s context, in what form, and when — so it reliably does the right thing.
The symptom
It wrote Width 7.5 into a field that expects microns — wrong units, empty result, wasted beamtime, no error.
02Primer · what the model actually sees

Everything happens inside the context window

On each call, the model sees only what we assemble into its context window — its entire working memory for that step. If a fact isn’t in the window, the model falls back on training memory, which is unreliable for exact, project-specific values.

03The problem

The procedure never entered the window

APEXA’s handbook knowledge lived in two places that never reached the context window before the action: a RAG store (only searched if explicitly triggered) and “Skills” that were named but never loaded. So the model set parameters from parametric memory — and guessed the units.

04Why the handbook was in RAG — yet still missed

Retrieval is a gamble; a pre-loaded Skill is a guarantee

The trap was in the knowledge base. But RAG is pull — it only helps if (a) a search actually fires and (b) that one-line needle out-ranks thousands of other chunks. At a parameter-writing step, neither held.

RAG storepull · ranked · conditional

Thousands of handbook chunks. A broad query (“set up FF-HEDM”) returns the top-k most similar — and the tiny “Width is µm, not px” line isn’t among them. Worse: while writing params the agent issued no knowledge query at all, so retrieval never ran.

Top-k retrieval / recall
RAG returns the k nearest chunks by embedding similarity. If the needle ranks below k, it’s simply absent — a recall miss.
Needle in a haystack
One critical line diluted among a large corpus is easy to miss — and bigger corpora make it harder, not easier.
Push vs. pull context
Skills push the right material in deterministically; RAG waits to be pulled, and only if asked.
05The fix · part 1 — learn

Pre-load the procedure — right place, before acting

Move the canonical Skill (the written procedure: fields, units, traps) into the system prompt of the relevant specialist agent — ahead of the moment it writes parameters. This is pre-loading, not just-in-time retrieval.

step 1
Request arrives
Routed to the Analysis agent.
step 2 · new
Inject Skill → system prompt
Handbook procedure loaded into the context window now.
step 3
Model writes params
Grounded in the procedure — units correct.

MIDAS reconstruction.
Why not just-in-time (JIT) retrieval? Reactive retrieval fires after the model already needs the fact — too late to stop the wrong value being written. Pre-loading puts the knowledge in the highest-salience slot before the decision. (Deep “why” questions still use RAG — see next slide.)
Pre-loading vs. just-in-time
When you assemble context: ahead of the action (into the system prompt) vs. fetched reactively mid-loop.
Skills
Packaged, reusable procedural context — a written SOP the agent loads, not just a tool name.
Grounding
Tying output to provided source (the handbook) rather than model memory.
06The fix · part 2 — enforce · result

Enforce what you can’t afford to prompt

Context alone is guidance — the model can still slip. So the unambiguous rules get a deterministic guardrail: a code-level check, independent of the model, that runs before dispatch.

Layer 2 · enforce
Deterministic guardrail

A hard check inspects the parameter file before the run starts. Units in pixels where µm is required → the run is blocked, with an actionable message. Like a hutch interlock: no “please remember,” just enforced.

⛔ Width is in µm, not pixels — 7.5 µm ≈ 0.04 px, rejects every peak. Nothing was run.
Layer 3 · depth
RAG, on demand

The full FF/NF handbook stays searchable for the deep rationale — unchanged, now backed by pre-loaded procedure (Layer 1) and the guardrail (Layer 2).

principle: don’t prompt what you can enforce.

08Case study · the pattern & the fix

One bug class, hit twice: a missing line becomes a degenerate default

The parameter file omitted two lines. Each fell back to a default that is not a safe no-op — it is a zero-width window that rejects the entire dataset. Same trap, two stages, both invisible until far downstream.

Act 1 · transforms · keep filter
Missing BoxSize

Default virtual-detector box has a zero Z-span (Zmin = Zmax = 0) — no spot lands exactly on it, so all 937 are dropped and InputAll.csv is zero-filled. Surfaced as mmap Data.bin failed.

BoxSize -10000.000000 0.000000 0.000000 0.000000
✓ Fix — permissive box: BoxSize -1e6 1e6 -1e6 1e6 → 937 real spots reach indexing.
Act 2 · transforms · seed filter
Missing Min/MaxOmeSpotIDsToIndex

Seed ω-window defaults to 0.0 / 0.0 — a single point at ω = 0°. The spots sit at ω ≈ −160°, so SpotsToIndex.csv ends up empty. The indexer still loads all 937 spots (so it looks like it ran) but gets 0 seeds → 0 grains. Surfaced as 0 / 0 seeds indexed.

MinOmeSpotIDsToIndex 0.0 MaxOmeSpotIDsToIndex 0.0
✓ Fix — open the window to the full sweep: MinOme -180 · MaxOme 180. The reference ±90 would clip the −160° spots.
✓ Confirmed on re-run seeds 0 → 279 (38 with non-zero data) 7 grains written to Grains.csv a ≈ 4.079 Å, SG 225 · confidence 0.62–0.91 c-omp over-segments the 2 true grains (parent + Σ3 twin) into ~6–7 fragments, as ground truth predicted
False lead worth remembering: the first guess — add RingNumbers 1 2 3 4 5 — was a no-op. Rings are derived from RingThresh; RingNumbers/RingRadii are outputs the transforms stage writes to paramstest, not inputs it reads. And re-running with --resume reused the stale zeroed files, so the "fix" never actually executed — always re-run clean into a fresh directory.
