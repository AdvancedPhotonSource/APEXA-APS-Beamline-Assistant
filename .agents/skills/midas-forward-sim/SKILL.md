## Forward simulation (MIDAS v11) — source of truth: `manuals/Forward_Simulation.md`

MIDAS ships **two** simulators. Pick by modality — they are NOT interchangeable.

| Modality | Tool | Binary | Output |
|---|---|---|---|
| **Far-field (FF)** | `run_forward_simulation` | `ForwardSimulationCompressed <ParameterFile> <nCPUs>` | continuous-intensity Zarr/ZIP images + optional spot CSV |
| **Near-field (NF)** | `run_nf_forward_simulation` | `simulateNF <ParameterFile> <InputMicFile> <OutputPrefix> [nCPUs]` | hit-count images + binary files + spot CSV |

> Both are **C binaries** requiring a built MIDAS clone. If `validate_midas_installation`
> doesn't show them, there is no build — do not claim a simulation ran.

---

## FF: `run_forward_simulation`

**Contract:** `ForwardSimulationCompressed <ParameterFile> <nCPUs>` — TWO arguments.
APEXA passes `n_cpus` as the required 2nd arg (default 4; set it to the machine's
physical core count for best speed). The tool rewrites a temp param file to inject
`InFileName` (your grain data) and `OutFileName` (your prefix), then runs the binary.

**Required / optional inputs (manual §1.2.1):**
- **Input grain data** (`InFileName`) — one of: `Grains.csv`, an EBSD text file
  (`X Y Z Eul1 Eul2 Eul3`, Euler in **degrees**), a `.vtk` (FE mesh), or `.bin`.
- **`hkls.csv`** — auto-generated by the bundled `GetHKLList`. For that to work the
  param file must carry `SpaceGroup`, `LatticeConstant`, and `Wavelength`.
- **`positions.csv`** — REQUIRED only when `nScans > 1` (one sample-offset value per
  scan, microns). The tool warns if it's missing; the binary will otherwise fail.
- **`IntensitiesFile`** (optional) — relative peak intensities; else equal intensity.

**Key param keywords (manual §1.2.2):** `Lsd` (µm), `Wavelength` (Å),
`OmegaStart/End/Step` (deg), `NrPixelsY`/`NrPixelsZ`, `px` (µm), `BC <y> <z>`,
tilts `tx/ty/tz`, distortion `RhoD/p0/p1/p2`, `LatticeConstant <a b c α β γ>`,
`PeakIntensity`, `GaussWidth` (spot blur, **pixels**), `EResolution <Δλ/λ> <nSamples>`,
`nScans`. Output control: `WriteSpots 0|1` (→ `SpotMatrixGen.csv`),
`WriteImage 0|1` (default 1; `0` skips images — faster if you only need spots),
`SimulationBatches N` (memory: `0`=auto, `1`=single-pass ~22 GB for 2048² ×1440,
`N>1`=batched, e.g. 72 → ~320 MB).

**Output (manual §1.3):** `<prefix>_scanNr_X.zip` — Zarr v2 inside a ZIP, data at
`exchange/data/`, `uint16` normalized so the brightest pixel = 15000. Plus
`SpotMatrixGen.csv` when `WriteSpots 1`.

## NF: `run_nf_forward_simulation`

**Contract:** `simulateNF <ParameterFile> <InputMicFile> <OutputPrefix> [nCPUs]` —
`nCPUs` optional, manual default 1. Produces **hit-count** images (pixel = how many
spots hit it), the format NF reconstruction expects — NOT continuous intensity.

**Input `.mic` (manual §2.3):** 4-line header (skipped) then per-grain rows; the
code reads `xs ys edgeLen ud eul1 eul2 eul3 confidence`.
> **TRAP — Euler angles in the `.mic` MUST be in RADIANS.** The code converts to
> degrees internally; degrees-in gives a silently wrong orientation. (manual §2.3)

**NF-specific param keywords (manual §2.2):** `nDistances <N>` (must precede the
per-layer `Lsd`/`BC` lines — ONE `Lsd` and ONE `BC` line per layer), omega
`StartNr`/`EndNr`/`OmegaStart`/`OmegaStep`/`OmegaRange <min max>` (repeatable) with
a matching `BoxSize <y1 y2 z1 z2>` per range, material `SpaceGroup`/`LatticeParameter`/
`Wavelength`/`MaxRingRad` (µm)/`RingsToUse` (repeatable)/`ExcludePoleAngle`, detector
`NrPixelsY/Z`/`px`/`tx/ty/tz`/`Wedge`. `WriteImage 1` adds `<prefix>.zip`;
`SaveReducedOutput` skips the full raw binary.

**Output (manual §2.4):** `<prefix>` (raw uint16, 8192-byte header), `<prefix>.bin`
(sparse `[row,col,frame,layer,count]`), `SpotsInfo.bin`, `SimulatedSpots.csv`, and
`<prefix>.zip` (4D Zarr `[nLayers,nrFiles,NrPixelsZ,NrPixelsY]`) when `WriteImage 1`.

## Traps & honest-status (both tools)

- **nCPUs is required for FF** — the binary contract is `<param> <nCPUs>`. Never omit it.
- **Exit 0 ≠ success.** A run can exit 0 and write nothing new (e.g. `WriteImage 0`,
  or geometry that produced no spots). Both tools verify outputs are **newer than run
  start** and downgrade to `status:"warning"` when nothing is fresh — read that note;
  don't report a stale file from a prior run as this run's result.
- **FF vs NF mix-up** — don't feed a `.mic` to the FF tool or `Grains.csv` to NF.
  NF needs the `.mic`; FF reads Grains.csv/EBSD/VTK/.bin.
- **Remote data** is refused fail-closed (outputs land next to the data; these C
  binaries aren't routed over SSH). Run on the data host or stage inputs locally.
- **PF/scanning** forward simulation (`SimulateScanning`) was removed in v11 —
  `scanning_mode` returns an error pointing to `midas_diffract` / `run_pf_hedm_workflow`.
