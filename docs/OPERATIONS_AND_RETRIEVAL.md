# Runtime visibility and retrieval generations

Operational traces are enabled without `APEXA_SHOW_TIMING`. Query, model-call measurements, client tool calls, instrumented MCP servers and owned subprocesses share correlation IDs. HTTP responses expose `X-APEXA-Trace-ID`; WebSocket tool/result messages include `trace_id`. MCP metadata carries IDs, never execution authority. `GET /api/traces/{trace_id}?after=0&limit=200` supports bounded diagnostic replay behind the same single-operator access boundary as other API routes.

The default sink is `~/.apexa/runtime/traces.sqlite3`, configurable with `APEXA_TRACE_DB`. A bounded background queue keeps writes off the event loop and retains the latest 20,000 events. `/api/status` reports queued, dropped and failed trace writes, event-loop lag and process RSS. Traces are best-effort diagnostics: a process crash can lose queued records. Acquisition/job records use their separate transactional event store. These diagnostics are not an immutable compliance log or a distributed tracing collector.

Only allowlisted measurements and identifiers enter traces. Prompts, arguments, file paths, usernames, results, stdout and exception messages are excluded. New interaction-log records also omit scientist content; old interaction logs are not rewritten. Protect and expire existing logs under the operator's data policy. Token measurements remain provider-dependent estimates; no cost is fabricated without actual usage/pricing evidence.

`/api/health/live` reports API liveness. `/api/health/ready` returns 503 unless required MCP servers are connected (`APEXA_REQUIRED_SERVERS`, default `core,midas`). Engine qualification and remote data-host reachability are reported separately as unverified/unprobed. Connectivity is not numerical qualification. `scripts/runtime_readiness.py --output /path/to/record.json` records current configured source hashes, declared tools, package versions and platform without launching engines or models.

The maintained product surfaces are React and CLI on the Linux/macOS runtime. Gradio, Trame and legacy HTML remain experimental pending lifecycle/parity checks; broad Windows installation instructions do not qualify POSIX worker ownership or locks. The retrieval service is extracted into `apexa_knowledge_service.py`, with a thin MCP wrapper retaining its public arguments. Loading and searching run outside the async MCP loop. Additional technique-adapter decomposition remains incremental.

## Bounded execution and browsing

Captured child stdout/stderr is bounded to 32 MiB combined by default (`APEXA_MAX_CHILD_OUTPUT_BYTES`). Exceeding the limit stops/reaps the owned process group and raises an explicit failure instead of silently truncating a scientific result. Write large logs/results to artifact files. This limit also applies to an SSH client's output; stopping the client does not establish remote cancellation.

The WebSocket layer retains task handles, admits one outstanding turn per socket and at most 16 globally, and cancels/drains them on service shutdown. A disconnected browser's accepted turn can finish and save its session; chat tasks themselves are not resumable across server crashes. Long scientific acquisition work uses the durable run store described in [ACQUISITION_RUNTIME.md](ACQUISITION_RUNTIME.md). File browsing uses `offset`/`limit` (default 100, maximum 500), reports total/next offset, and applies hidden-file filtering before pagination. Directory pages are a live view: refresh after files are added or removed.

## Embeddings and knowledge updates

Embedding loading requires an immutable 40-character model commit in `APEXA_EMBED_REVISION`, or resolves an already staged Hugging Face snapshot without a network request. Remote model code is disabled by default. The ordinary path retains `trust_remote_code=False`. A caller's `offline=False` cannot override the deployment's data/offline policy.

Remote model code requires both `APEXA_EMBED_TRUST_REMOTE_CODE=1` and a reviewed code-repository commit in `APEXA_EMBED_CODE_REVISION`. The qualified remote path is limited to **sentence-transformers 5.7.0 / transformers 4.57.6**, with a saved **Transformer → Pooling → optional Normalize** text pipeline. APEXA validates pinned module/configuration files before constructing model code, directly calls the public `Transformer.load` with separate model/config code pins, and constructs `SentenceTransformer` from those loaded modules. This bypasses the general saved-module resolver, which drops the nested model code pin in this SDK. Tokenizer/processor remote code remains disabled; it receives the already pinned config object and model-revision-bound tokenizer assets. Unknown module classes/settings, alternate tokenizer paths, PEFT adapters, custom processors/tokenizers and unqualified SDK versions are explicitly refused. No weaker retry or substitute embedder is used.

The cached Nomic v1.5 manifest was inspected read-only: it uses Transformer plus mean Pooling, a saved 8192-token limit, and a built-in BERT tokenizer; its config/model code references a separate Nomic code repository. That shape is supported without changing its saved architecture, pooling, prompts or truncation. The returned embedding identity records the loader, SDK pair and configuration SHA-256 values in addition to model/code commits. Existing index identities that lack these facts require a new immutable generation under reviewed settings; do not relabel an old index as equivalent. Offline constructor-boundary tests verify pin propagation and preservation of the saved pipeline using synthetic manifests and tiny in-memory weights. **No live Nomic embedding-equivalence or numerical-quality run was performed.** No operator model files, cached weights or settings were modified.

Indexing builds a new immutable Chroma collection. It validates a nonempty completed build, then atomically replaces `knowledge_base/data/hedm_knowledge-active.json`; it never deletes the active collection before rebuilding. Failure preserves the old pointer. Old collections remain available for in-flight readers and reproducibility; an operator can archive/retire them after ensuring no active or frozen study manifest references them. Query embedding identity must match the published index.

Each new chunk carries a stable source ID, source-file SHA-256, chunk-content SHA-256 and knowledge role (`procedure`, `historical_observation`, or `reference_material`). Retrieved text remains untrusted evidence, including procedures. Legacy collections remain readable but explicitly report unverified embedding/generation provenance; they cannot use the immutable sparse cache. Reindex them under reviewed embedding settings to obtain the new contract.

Hybrid retrieval caches BM25 data by collection identity, immutable generation and filter. Inverted token postings avoid rebuilding/scanning Python token dictionaries on each query. The cache is capped at eight entries with conservative 64 MiB accounting; unknown mutable collections are not cached. Atomic publication assumes a qualified local filesystem and trusted index writer. It does not prevent direct out-of-band mutation of Chroma storage or establish independent scientific truth.
